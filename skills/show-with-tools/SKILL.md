# show-with-tools

The user's site (a gitwebsite site) has ~350 interactive browser tools at `/tools/<slug>/`. Most
take URL parameters and `?example=` presets, so a link can open a tool already showing exactly
what you mean. The gitwebsite MCP server opens them in a native window of the gitwebsite app,
from the app's local preview (no site chrome).

**Which tool?** See [tools-index.md](tools-index.md) — every tool by category with its parameter
names and presets (generated by `gw tools index`; regenerate with `scripts/gen-tools-skill-index`).
Or search: `tools_list` with `q` (words) or `category`.

## Workflow

1. **Pick the tool** from the index or `tools_list {q: "…"}`.
2. **Read it**: `tool_info {slug}` — the exact parameter names and meanings, the presets and
   what each shows, the tabs (`#hash`), and example links from its page. Never guess a
   parameter name; one the tool doesn't know is silently ignored.
3. **Prefer a preset** (`example`) when one shows what you mean; add `params` to adjust it
   (parameters override the preset). Otherwise build it from `params`.
4. **Open it**: `tool_open {slug, params, example, hash, title}` — reuses the tool's window
   (`window: "new"` for a second one). Give it a title that says what it shows.
5. **Check it** (optional): `tool_screenshot {id}` returns a PNG of the window, so you can see
   whether it shows what you intended. `tool_windows` lists windows; `tool_close {id}` closes one.
6. Tell the user what to look at, and give them the `public_url` from the result as a link they
   can keep or share.

## Rules

- **Keep the user's data out of URLs** unless they asked for it: no credentials, tokens, private
  hostnames, personal data or proprietary code in `params`. Tools that connect to real systems
  (Kafka, Redis, Postgres, Docker, Kubernetes, git) use the app's companion relays and their own
  settings — don't put connection secrets in links.
- Values are plain strings; `tool_open` URL-encodes them. Multi-line text (Mermaid, DOT) is fine.
- If `tool_open` says the app isn't running, give the user the `public_url` (the same view on
  https://geekychris.github.io) and mention that the gitwebsite app can open it in a window.
- One window per idea; reuse it while iterating (same slug → same window).
- `companion_status` reports whether the app runs and which relays (Docker socket, Kubernetes
  contexts, TCP allow-list) are available, for tools that need them.

## Quick picks

| To show | Tool | How |
|---|---|---|
| Flowchart, sequence, architecture sketch | `diagrams` | `mmd=<Mermaid>` + `hash: "mermaid"`, or `dot=<Graphviz>` (+ `engine`) |
| A function, polar curve, integral | `graph` | `f=sin(x);x^2/4`, `x=-6,6`, `shade=0,pi` |
| Symbolic maths | `cas` | `expr`, `op`, `var` (see tool_info) |
| Kafka / Kubernetes / Raft / Spark / Flink behaviour | `kafka-sim`, `k8s-sim`, `raft-sim`, `spark-sim`, `flink-sim` | a preset (`example=…`), then `step`, `seed` |
| Caching, queueing, load balancing | `cache-sim`, `queueing`, `load-balancing` | presets |
| Cloud architecture | `aws-builder`, `gcp-builder` | presets |
| Git history and commands | `git-trainer` | `lesson` |
| Circuit | `circuit-sim` | `ex=rc` / `rlc` / … + `hash: "ac"` |

Confirm each with `tool_info` — the index above is a starting point, not the contract.
