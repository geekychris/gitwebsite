= Templates and layouts
:toc:

Templates are Tera (Jinja-like) files. Every page extends `base.html`.

The default theme is built into gitwebsite (`crates/gw-core/theme/`): its templates and the
assets they use (`css/site.css`, `js/site.js`, the playground scripts, `tools/tools.js` and
`tools.css`, `images/favicon.svg`). A site needs no templates of its own. A file in the site's
`templates/` replaces the built-in template of the same name, and a file in its `static/`
replaces the built-in asset at the same path, so a site can change one template and keep the
rest. `gw init` copies the whole theme into a new site (unless `--no-theme-copy`) so it is easy
to find and edit; delete a copied file to go back to the built-in one.

| `project.html` | Project pages with their update timeline
| `app.html`, `playground.html`, `exploration.html` | Lab pages (explorations also get `series`: `name`, `part`, `count`, `prev`, `next`)
| `list.html` | `/articles/`, `/projects/`, tag pages

| `lab.html`, `publications.html`, `404.html` | Their pages
| `models.html`, `models_grid.html`, `model.html` | The 3-D models gallery `/models/` (when no post has `models::gallery[]`), its grid (also rendered into a post by `models::gallery[]`: `cards`, `projects`, `show_chips`, `embedded`), and each model's page (`m` with `used_in`; `heading` and `index_url`: where the gallery is) — see link:integrations.adoc#models-gallery[Integrations]
| `code.html`, `code_project.html` | The code catalog `/code/` (`code`: `title`, `intro`, `groups` of `cards`, `tags`, `count`) and each project's page (`p`: the card, with `related`, `post_url`, `logo` or `monogram`/`hue`) — see link:integrations.adoc#code-catalog[Integrations]

== What templates can use

Every page: `site` (title, tagline, base_url, author, description, links), `nav`, `page_path`,
`page_title`, `noindex`, `areas_tree`, `build_year`, and `analytics_id`.

`analytics_id` is the Google Analytics 4 measurement id from `site.google_analytics` in
site.yaml (e.g. `google_analytics: G-XXXXXXXXXX` under `site:`), present only when it is a
well-formed `G-` id. The default `base.html` adds the gtag.js snippet when it is set; the snippet
does nothing on `localhost`/`127.0.0.1`, so previews aren't counted. A site with its own
`templates/base.html` needs the same `{% if analytics_id %}…{% endif %}` block before `</head>`.

`base.html` has an empty `{% block head %}` in `<head>` for a page's own stylesheets and scripts
(the models gallery pages use it); a site's own `base.html` needs it too.

Item pages add `item`, and listings add `entries`, each an item view with: `id`, `kind`,
`kind_label`, `title`, `url`, `slug`, `date_human`, `date_iso`, `updated_human`, `summary`,
`hero_url`, `area_links` (path, title, url), `tags`, `project_title`, `project_url`, `repo`,
`app_url`, `embed`, `featured`, `pinned`, `pin_order`, `reading_minutes`, `html` (the rendered body), `uses_tools` (the
tools its `tool::` blocks show: slug, title, url), `languages` (its playground languages: id, label), `series` and
`series_part` (explorations), and `attrs`
(every header attribute, for custom fields).

Extra context: home gets `pinned`, `featured`, `posts` (latest six), `projects`, `apps` — each list
leaves out what an earlier one holds, so nothing repeats (the complete lists are `all_posts` and
`all_projects`); projects get
`updates`; posts get `related`; area pages get `area` and `crumbs`; the Lab gets `explorations`,
`playgrounds` (with `languages`: id, label, count), `sketches`, `rosetta`, `apps` and `lab_tools` (`:lab: true`); publications gets `groups`.

== Changing the look

Styles are in `site/static/css/site.css`, built on CSS custom properties at the top of the
file (colours, radius, widths, fonts) with a dark-mode block. Behaviour (search, code
highlighting, playgrounds) is in `site/static/js/site.js`.
